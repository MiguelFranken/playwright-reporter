---
title: Retention
description: How long artifacts and run history are kept.
---

Both policies are **off** until a superadmin turns them on, so an upgrade never deletes anything by itself.

## Artifacts

**Administration → Storage** sets how long screenshots, videos and traces are kept: a lifetime in days, counted from the
upload, and optionally a shorter one per kind. A sweep deletes expired objects from the store and marks them expired;
the run keeps every result, error and step, and the artifact's page says it expired.

Some review images are kept however old they are:

- **Approved baselines**: the image each checkpoint is compared against. Always kept.
- **Library screens**: what the [library](/docs/using/visual-review#the-library) shows for every branch or pull request
  kept in it, and the runs pinned there.
- **Commented flows**: every image of a flow — one test's checkpoints in one run, every variant — on which a comment
  thread is still open. Once the thread is resolved, the flow ages out like any other.

**Library screens and commented flows** on the same page switches the last two off: *Expire with their lifetime*
lets them go with the lifetime of their kind. The preview before saving shows what that would free.

With `S3_RETENTION=lifecycle` the bucket expires objects by age alone, and none of these exceptions apply.

On S3, `S3_RETENTION=lifecycle` lets the bucket expire objects itself: uploads are tagged with their kind, and saving
the policy writes one lifecycle rule per kind.

## Run history

**Administration → Database** sets how long finished runs are kept, separately from artifacts. The page shows how full
the database is, how fast it grows and what the saved policy would delete next. A sweep deletes finished runs older
than the lifetime — except the newest few of every project — with their artifacts, then tests no run refers to, the
live event log of finished runs, and expired sessions and tokens. **Purge history** deletes every finished run at once.

## When sweeps run

| Trigger | |
| --- | --- |
| A daily cron | Vercel Cron in production, or any cron calling `/api/cron/artifact-retention` and `/api/cron/data-retention` with `CRON_SECRET`. |
| A finished run | When no sweep started in the last 12 hours, or the last one ran out of time with work left. |
| **Run now** | The button on each admin page. |

Every sweep has a time budget, so it fits in one request (on Vercel, a function's maximum duration). A sweep that runs
out of time with work left calls its cron endpoint again, and that call carries on in a fresh request with a budget of
its own, until nothing is due. This needs `CRON_SECRET`, and `BASE_URL` when the app is not on Vercel, so the app can
reach itself. Without them, what is left waits for the next finished run or the next daily cron.
