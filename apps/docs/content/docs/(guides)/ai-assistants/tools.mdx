---
title: Tools
description: The tools the MCP server offers, to read test history and test cases, and to edit test cases.
---

Three toolsets; a connection can ask for fewer with `?toolsets=core`. The full reference with every parameter is
generated from the code: [`docs/mcp-tools.md`](https://github.com/MiguelFranken/playwright-reporter/blob/main/docs/mcp-tools.md).

| Toolset | Tools |
| --- | --- |
| `core` | `whoami`, `list_filters`, `list_runs`, `get_run`, `list_run_results`, `get_result`, `find_tests`, `get_test_history`, `project_health`, `list_test_cases`, `get_test_case`, `list_test_suites` |
| `debug` | `get_failure_context` (start here for a failing test), `check_flakiness`, `summarize_failures`, `compare_runs`, `verify_fix`, `get_artifact`, `get_rerun_command` |
| `write` | `create_test_case`, `update_test_case`, `create_test_suite`, `delete_test_suite`, `link_test_case`, `adopt_tests` |

`core` and `debug` only read. The `write` toolset edits [test cases](/docs/using/test-cases) and is offered only to a
personal access token created with **Read, and edit test cases**; your role in the team still decides what a call may
change, so a viewer's token cannot write. Every edit is a new version in the case's history, with you as its author.

Verdicts — flaky, deterministic, fixed — are computed from the stored attempts, not guessed by a model, and say which
fixes the evidence rules out. Clients with slash commands also get the prompts `triage_run`, `debug_test`,
`investigate_flake` and `branch_check`.

The [REST API](/docs/api) answers from the same code: every reading tool but the prompts has a REST endpoint.
