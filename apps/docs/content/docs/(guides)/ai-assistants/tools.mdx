title: Tools
description: The tools the MCP server offers, to read test history and test cases, and to edit test cases.
---

Three toolsets; a connection can ask for fewer with `?toolsets=core`. The full reference with every parameter is
generated from the code: [`docs/mcp-tools.md`](https://github.com/MiguelFranken/playwright-reporter/blob/main/docs/mcp-tools.md).

| Toolset | Tools |
| --- | --- |
| `core` | `whoami`, `list_filters`, `list_runs`, `get_run`, `list_run_results`, `get_result`, `find_tests`, `get_test_history`, `project_health`, `list_test_cases`, `get_test_case`, `list_test_suites`, `list_uncovered_tests`, `list_feedback_requests`, `list_review_checkpoints`, `get_review_checkpoint`, `list_review_threads`, `list_library`, `get_library_flows`, `list_visual_diffs`, `get_visual_diff`, `get_visual_diff_analysis`, `list_visual_ignore_rules`, `preview_visual_ignore_rules` |
| `debug` | `get_failure_context` (start here for a failing test), `check_flakiness`, `summarize_failures`, `compare_runs`, `verify_fix`, `get_artifact`, `get_rerun_command`, `get_visual_diff_image` |
| `write` | `create_test_case`, `update_test_case`, `bulk_update_test_cases`, `create_test_suite`, `delete_test_suite`, `link_test_case`, `adopt_tests`, `review_checkpoint`, `comment_on_review`, `resolve_review_thread`, `set_library_reference`, `set_visual_ignore_rules`, `update_visual_ignore_rules`, `analyze_visual_diff`, `decide_visual_suggestion` |

`core` and `debug` only read. The `write` toolset edits [test cases](/docs/using/test-cases), decides about and comments on [review checkpoints](/docs/using/visual-review), sets which areas are left out of visual comparisons, and what the [library](/docs/using/visual-review#the-library) keeps, and is offered only to a
personal access token created with **Read, and edit test cases**; your role in the team still decides what a call may
change, so a viewer's token cannot write. Every edit is a new version in the case's history, with you as its author.

Verdicts — flaky, deterministic, fixed — are computed from the stored attempts, not guessed by a model, and say which
fixes the evidence rules out. Clients with slash commands also get the prompts `triage_run`, `debug_test`,
`investigate_flake`, `branch_check`, `fix_visual_feedback` (work through every open request on a branch's screenshots:
fix, re-run only the producing tests, check the new images against the originals — replies only if you say so) and
`investigate_visual_diffs` (why screens differ between two runs, region by region) and `organize_tests` (sort the
Playwright tests no case covers yet into existing or new cases and suites). For more, ready to paste into any agent,
see [Prompt recipes](/docs/ai-assistants/prompts).

The [REST API](/docs/api) answers from the same code: every tool has a REST endpoint, and the `write` tools take a
token with the same scope there.
